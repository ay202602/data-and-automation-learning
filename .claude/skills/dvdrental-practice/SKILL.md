# dvdrental SQL練習フロー

ユーザーは Python/SQL を学習中で、**手打ちで書くこと**を重視している。
そのため、このスキルの役割は「答えを書いてあげる」ことではなく、
「考え方の手順と書き方を理解したうえで、自分で打てる状態にする」こと。

## 前提（ユーザーのレベルと環境）
- SQLは CTE・ウィンドウ関数まで理解済み。ただし**構文単位では未習のものがある**ので `references/learned.md` で判定する
- DBは PostgreSQL（dvdrental）。`practice/sql/basic/` の SQLite 構文（`strftime` など）は使わない
- テーブル構成と結合キーは `references/dvdrental_schema.md` を参照する（推測でカラム名を書かない）

## 回答フロー（この見出し順で出力する）

練習項目が提示されたら、次の順で答える。順番を固定しているのは、
「何を出したいか → どう考えるか → 新しい道具 → 実際の書き方」の順だと、
ユーザーが自分で組み立て直せるため。

### 1. 練習の目的
- どんなデータが欲しいのかを1〜2行で言い換える（出力する列のイメージも示す）
- 既存の `.sql` と同様、ファイル先頭に書くコメント案を添える（例: `-- 月ごとの売上と前月比を出力するクエリ`）

### 2. 使うテーブルと結合キー
- 必要なテーブルを、結合する順に `A → B (キー)` の形で示す
- 迷いやすい点（`rental` と `payment` どちらを起点にするか等）があれば一言で理由を書く

### 3. 手順
- クエリを組み立てる考え方を番号付きで示す（例: ① 月ごとに集計 → ② 前月の値を横に並べる → ③ 差分から比率を出す）
- CTE に分ける場合は「どこで区切るか・なぜ区切るか」を書く（1つのCTE＝1つの目的）

### 4. 未習構文の解説
- `references/learned.md` と照合し、**載っていない構文だけ**を解説する。既習のものは再説明しない（読む負担を増やさないため）
- 未習構文が無ければ「今回は既習の構文だけで書けます」と明記して飛ばす
- 解説は初学者向けに、次の3点セットで書く
  - 何をするものか（日常の言葉で1〜2文）
  - 最小の例（dvdrentalのテーブルを使った短い例。可能なら結果のイメージも）
  - 今回なぜ必要か（これが無いと何が困るか）

### 5. クエリ提案
- 長くなる場合は**ブロック（CTE）ごと**に分けて提示し、各ブロックの直後に「なぜこう書くか」を要点でまとめる
- 最後に全体をつなげた形も示す
- コードは**提案のみ**。ファイルの作成・編集・保存はユーザーから指示があるまでしない（手打ち学習のため）
- スタイルは既存の `practice/sql/practice/*.sql` に合わせる
  - テーブルに `AS` でエイリアスを付け、カラムにも付ける（`cr.customer_name`）
  - 結合キーが同名なら `USING(...)`、異なるときだけ `ON`
  - 大文字キーワード、4スペースインデント、段階ごとに CTE を分ける

### 6. 締め
- 保存する場合のファイル名案（`dvdrental_内容.sql`、snake_case）
- 今回初めて出てきた構文があれば「`learned.md` に追記しますか？」と確認する（勝手に書き換えない）
- コミットメッセージ案が欲しいと言われた場合は `add: ○○の.sqlファイルの追加` ＋ 本文に「概要」として学んだ内容を箇条書き

## 学習済みリストの更新
ユーザーが追記を承認したら `references/learned.md` に1行追加する。
追加の際は構文名・1行メモ・初出のファイル（なければ「今回」）を書く。

## 回答例（抜粋・形式の参考）
入力: 「顧客ごとの累計売上を日付順に出したい」
出力の骨子:
1. 目的: 顧客別に、支払日順の累計売上が増えていく様子を一覧にする
2. テーブル: `customer` → `payment` (customer_id)
3. 手順: ① payment を日単位に集計 → ② 顧客ごとに日付順で足し上げる
4. 未習構文: `SUM() OVER (PARTITION BY ... ORDER BY ...)`（累計の作り方）を解説
5. クエリ: CTE ごとに提示し、理由を添える
6. ファイル名案 `dvdrental_running_total.sql`、learned.md 追記確認
